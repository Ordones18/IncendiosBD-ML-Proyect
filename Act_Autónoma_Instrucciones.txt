Tema de la actividad: 
Infraestructura de Persistencia Híbrida y Despliegue de Modelos de Machine Learning para la Resolución de Problemas de Analítica Predictiva.
Objetivos general de la actividad:  
Diseñar e implementar una solución analítica e infraestructural integral que combine una arquitectura de persistencia híbrida (SQL Server y MongoDB) para asegurar la gestión, gobernanza e integridad de datos masivos, con el entrenamiento, evaluación y despliegue de modelos de Machine Learning (supervisados y no supervisados) orientados a resolver una problemática real del entorno actual.
Objetivos específicos: 
Diseñar e implementar un repositorio relacional normalizado en SQL Server, optimizando el rendimiento de consultas analíticas masivas mediante la aplicación de índices y estructuras programables avanzadas.
Integrar un componente documental NoSQL (MongoDB) para resolver necesidades analíticas flexibles, simulando una arquitectura de persistencia híbrida real.
Garantizar la seguridad, auditoría mediante triggers y continuidad operativa de la información a través de un plan estratégico de respaldos y recuperación ante desastres (DRP).
Desarrollar un pipeline reproducible de preparación y transformación de datos utilizando Python en entornos Jupyter Notebook, justificando técnicamente las decisiones tomadas en el preprocesamiento.
Construir, optimizar y comparar algoritmos de aprendizaje supervisado y no supervisado, sustentando la selección de la solución óptima a través de métricas estadísticas avanzadas.
Desplegar una aplicación interactiva o tablero de control (utilizando Streamlit) que permita interactuar en tiempo real con los datos y los modelos generados.

Instrucciones:
Requisitos del Dataset
Cada grupo seleccionará un dataset público que cumpla con las siguientes condiciones mínimas:
Mínimo 10,000 registros.
Mínimo 15 variables (columnas) que incluyan tanto datos numéricos como categóricos.
Ingeniería de Datos y Arquitectura de Persistencia Híbrida
Diseñar el modelo entidad-relación normalizado (en SQL Server). Queda estrictamente prohibido cargar el dataset en una sola tabla plana. Se deben definir llaves primarias, foráneas y restricciones de integridad.
Poblar la base de datos de manera eficiente y automática. Pueden realizarlo mediante el asistente gráfico de SSMS (Import and Export Data) o automatizado mediante código Python con la función pandas.DataFrame.to_sql().
Crear vistas estructuradas específicas para el consumo de los algoritmos y aplicar índices (Clustered / Non-Clustered) que minimicen el costo de lectura de las consultas masivas.
Implementar una base de datos documental híbrida. Cada grupo utilizará MongoDB para la persistencia del Registro de Experimentos de Machine Learning. Cada vez que un modelo sea entrenado, se guardará de forma automática un documento en formato JSON que almacene: la fecha, el nombre del algoritmo, los hiperparámetros utilizados y las métricas obtenidas (estos son los campos como tal que deben usar en MongoDB)
Seguridad y Continuidad Operativa SQL
Programar triggers que registren automáticamente en una tabla histórica cualquier inserción, modificación o eliminación efectuada en las tablas críticas de datos.
Configurar scripts de asignación de privilegios (GRANT/REVOKE) creando al menos dos roles diferenciados: un rol analítico (permisos de lectura sobre vistas) y un rol administrador (control total de la infraestructura).
Implementación del DRP, diseñar una estrategia de copias de seguridad (Backups completos, diferenciales o de logs transaccionales). En la defensa práctica, se simulará un fallo crítico y el grupo deberá restaurar la operatividad total mediante código SQL.
Flujo de Trabajo de la asignatura de Machine Learning
Conectar Jupyter Notebook con SQL Server utilizando librerías de Python (pyodbc o SQLAlchemy) para extraer los datos mediante consultas optimizadas.
Realizar la limpieza de nulos y duplicados, transformación de variables categóricas y el escalamiento de variables numéricas, es decir, todo el preprocesamiento de datos.
Aplicar algoritmos de agrupamiento como K-Means para encontrar patrones ocultos en el dominio y definir el número de grupos óptimo mediante métodos científicos como el Método del Codo o el Coeficiente de Silueta.
Para el modelado Supervisado (Predicción o Clasificación) definir una variable objetivo. Dividir los datos obligatoriamente en conjuntos de entrenamiento (70-80%) y prueba (20-30%) fijando un estado aleatorio (random_state=42) para garantizar la reproducibilidad. Entrenar y comparar al menos dos modelos diferentes (por ejemplo Regresión Logística vs. Árboles de Decisión, o Regresión Lineal vs. Random Forest).

Puntaje
1. Diseño, normalización y gobernanza de la Base de Datos SQL
Modelo ER completamente normalizado (3FN o superior), relaciones correctamente justificadas, PK/FK implementadas, integridad referencial validada, triggers de auditoría, gestión de roles y permisos, evidencia funcional del DRP mediante restauración exitosa.
Modelo correctamente normalizado con mínimas inconsistencias. Implementa PK/FK y mecanismos básicos de auditoría, seguridad y recuperación.
Modelo funcional con algunas deficiencias de normalización o documentación. La gobernanza se implementa parcialmente.
Modelo parcialmente funcional, uso predominante de tablas planas o relaciones incorrectas. Escasa evidencia de seguridad o recuperación.
No presenta diseño ni implementación de base de datos.

2. Implementación de la arquitectura de persistencia híbrida (SQL Server + MongoDB)
Integra exitosamente SQL Server y MongoDB dentro de una arquitectura coherente. Justifica técnicamente el uso de ambos motores. Implementa almacenamiento estructurado y documental, garantizando trazabilidad y consistencia de la información.
Integra ambos motores y demuestra funcionalidad adecuada, aunque con limitaciones menores de diseño o justificación.
Implementa parcialmente la persistencia híbrida. Uno de los motores presenta uso limitado o poco justificado.
Implementación incompleta o sin integración real entre los motores de almacenamiento.
No presenta evidencia de persistencia híbrida.

3. Aprendizaje no supervisado
Aplica correctamente técnicas de clustering (K-Means u otras), determina científicamente el número óptimo de grupos mediante métodos como Codo o Silueta, interpreta patrones encontrados y relaciona los hallazgos con la problemática estudiada.
Implementa adecuadamente el modelo y utiliza criterios razonables para definir grupos, con interpretación suficiente de resultados.
Ejecuta el algoritmo requerido pero presenta análisis limitado de los patrones encontrados.
Aplicación incorrecta del algoritmo o interpretación insuficiente de los resultados.
No presenta aprendizaje no supervisado.

4. Aprendizaje supervisado y despliegue del modelo
Define correctamente la variable objetivo, compara al menos dos modelos, selecciona métricas apropiadas, justifica el modelo final y desarrolla una aplicación funcional que realiza inferencia en tiempo real con integración a las bases de datos.
Cumple los requisitos de entrenamiento, comparación y despliegue con pequeñas limitaciones técnicas o analíticas.
Presenta entrenamiento y despliegue básicos, con escasa justificación de resultados o desempeño.
Implementación incompleta o con errores que afectan la validez de los resultados.
No presenta modelado supervisado ni despliegue.

Los datos cumplen las condiciones solicitadas, son confiables y han sido preprocesados adecuadamente (conexión, limpieza, tratamiento de nulos, duplicados, transformaciones y escalamiento).
